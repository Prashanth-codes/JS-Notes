OOP= Object-Oriented Programming

We organise code around objects instead of functions.
An object contains Data(properties) and Behaviour(methods)
Instead of writing scattered functions, we group related things
together.

Its helps us by better structure, reusability, maintainability etc

We can implement oops in two ways:
1) Traditional OOP(Function-based prototyping)
2) Classes(ES6)

**Traditional methods
JS is not class-based originally. It is Prototype-based language
Before ES6, OOP was done by using
1) constructor functions
2) Prototypes
3) Object.create()

1) Constructor functions
Constructor functions is used to create multiple similar objects.

EX: function Person(name,age){
		this.name = name;
		this.age = age;
	}
	const p1 = new Person("Prashanth",20);
	const p2 = new Person("Ram",20);
	
	Explanation:
	Person is blueprint
	new creates object
	this refers to newly created object.

2) Prototypes:
	To add methods
	EX: ❌
	function Person(name){
		this.name = name;
		this.greet = function(){
			console.log(this.name)
		}
	}
	👉Problem: Every object gets separate copy of greet.
	
	Correct way:✅
	function Person(name){
		this.name = name;
	}
	Person.prototype.greet = function(){
		console.log(this.name);
	}
	const p1 = new Person("prashu");
	const p2 = new Person("Ram");
	p1.greet();
	
	👉Only one greet function exists, all objects share it
	So memory efficient
	
Prototype chain lookup:
	p1.greet()
	So js checks:
	1) Does p1 have greet? -> NO
	2) Go to p1.proto -> Person.prototype
	3) Found greet -> Execute
	
	This is called Prototype Chain Lookup.
	
3) Object.create(): It is used in implementing inheritance
	So while inheriting will use
	1) call: to inherit properties
	2) Object.create(): to inherit methods

Inheritance:
The capability of a class to derive properties and characteristics
from another class is called Inheritance.
Sub-class: The class that inherits from another class.
Super-class: The class whose properties are inherited by a sub-
	class is called Super-class
	EX:
	class Animal{
		constructor(name){
			this.name = name;
		}
		speak(){
			console.log("Animal makes sound");
		}
	}
	
	class Dog extends Animal{
		constructor(name, breed){
			super(name);
			this.breed(name);
		}
		bark(){
			console.log("Dog barks");
		}
	}
	const d = new Dog("Tommy","Labrador");
	d.speak();
	d.bark();
	
Polymorphism:
Ability of different objects to responf to the same method in 
different ways.
👉Same method name, different behaviour, decided at runtime

👉 In JS, polymorphism mainly happens through method overriding.

** Method overloading
Defining multiple methods with the same name but different paras
list within the same class.
It is compile-time polymorphism.

👉JS is a:
	dynamically typed
	does not check parameter types,count
	does not create method signatures
So, overloading is not possible in JS
EX:
	class Calculator {
    add(a,b){
		    return a+b;
		}
		add(a,b,c){
		    return a+b+c;
		}
	}
	const c = new Calculator();
	console.log(c.add(1,2));
	console.log(c.add(1,2,3))
	
	Output:
	NaN //second one overwrite firstone
	6

EX 1: Parent and child class
	class Parent {

	console.log(obj.add(1,2,3));

Method Overriding:
Child class replaces parent class method with same name.
class Parent{
	show(){
		console.log("Parent method");
	}
}
class Child extends Parent{
	show(){
		console.log("Child method");
	}
}
const obj = new Child();
obj.show();

Output:
Child method.

** Encapsulation:
	Keeping the data and methods together and restricting direct
	access to data.
	
	EX:
	class BankAccount {
		#balance; //private field is declared using #
		constructor(owner, balance){
			this.owner = owner;
			this.#balance = balance;
		}
		deposit(amount){
			this.#balance+=amount;
		}
		getBalance(){
			this.#balance;
		}
	}
	const acc = new BankAccount("prashanth",1000);
	acc.deposit(500);
	console.log(acc.getBalance());
	
	Output:
	1500
	
	Ex:
	console.log(acc.#balance);
	
	Output:
	Error
	This is called encapsulation.
	
**  Abstraction
Hiding internal implementation details and showing only the
essential features to the user.
Js does not have true abstract classes like java, but we can
simulate abstraction using classes, functions, private fields etc
EX:
	class Car{
		start(){
			this.#igniteEngine();
			console.log("car started");
		}
		#igniteEngine(){
			console.log("Engine ignition process");
		}
	}
	const car = new Car();
	car.start();
	
	Output:
	Engine ignition process
	Car started
	
	Ex: car.$igniteProcess();
	Output: Error
